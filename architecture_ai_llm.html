Arquitetura técnica validada

Harness de agentes: padrões Claude corretos, extensível a GPT, Gemini e modelos locais

O desenho abaixo separa a arquitetura nativa inspirada no Claude Agent SDK/Claude Code da camada corporativa provider-neutral. Assim, Skills, Hooks, Subagentes, MCP, permissões e sessões permanecem coerentes com os patterns da Anthropic, enquanto o Router e o Model Gateway podem escolher outros provedores quando a aplicação — e não o Claude Code — implementa essa abstração.

Crítica da imagem anterior

O que foi preservado e o que foi corrigido

A imagem original tinha ótima cobertura visual, mas misturava componentes genéricos, recursos do Claude Code e decisões corporativas como se todos pertencessem ao mesmo produto.

1

Skills reposicionadas

Não são meras funções “dentro do agente”. São pacotes de instruções, scripts e recursos, carregados sob demanda e utilizáveis pelo agente principal, subagentes ou invocação direta.

2

Hooks como lifecycle

O modelo “pré/meio/pós” é didático, porém incompleto. A arquitetura correta os trata como eventos determinísticos em sessão, ferramentas, permissões, término e notificações.

3

Agent loop, não pipeline rígido

Planner e Executor são opcionais. O núcleo é um ciclo: observar contexto → decidir → agir com ferramentas → verificar → repetir ou encerrar.

4

Gateway multimodelo separado

O Claude Code não deve ser representado como roteador nativo para GPT/Gemini. A escolha multimodelo fica na camada neutra da aplicação, por adaptadores de provedores.

5

Controles transversais

Guardrails, permissões, observabilidade, orçamento e auditoria não são uma etapa única: interceptam entrada, contexto, modelos, ferramentas e saída.

Aprendizado
Leitura correta e princípio de UX: o mapa utiliza progressive disclosure: todos os componentes permanecem disponíveis, mas somente a espinha dorsal aparece por padrão; relações transversais surgem no contexto certo. Arquitetura: não existe um único diagrama oficial “canônico” da Anthropic contendo todos esses blocos. Este mapa é uma síntese de produção que preserva os patterns oficiais — agentes simples e componíveis, contexto enxuto, tools claras, Skills sob demanda, Hooks determinísticos, subagentes isolados, MCP, permissões, sessões e avaliações — e adiciona as camadas corporativas necessárias para uma plataforma bancária.

Feedback
Princípio da visão: parâmetros como PD 12, PD LT, LGD, EAD e CCF não são produtos isolados. Eles dependem de dados certificados, desenho amostral, validação, calibração, MLOps, monitoramento e governança. Da mesma forma, IRRBB/EVE e NII dependem de modelagem de fluxo de caixa, comportamento, curvas e cenários. A camada de Risk Intelligence integra esses motores sem substituir a decisão humana nem as regras determinísticas.
